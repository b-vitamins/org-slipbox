#+title: org-slipbox Android Continuous Integration

* Jobs

The =ci= workflow adds =android= and =android-device= alongside the Rust, Elisp
and web checks. Releases reuse it through =workflow_call= without inputs.
See [[file:android-build.org][Android build instructions]] and [[file:android-native.org][native packaging]].

=android= runs on =ubuntu-latest= and checks:

- debug, instrumentation and unsigned release assembly;
- unit tests and lint;
- native packaging and private-storage exclusions;
- provisioning and device-gate shell tests.

It uploads lint and unit-test reports and records APK digests. Gradle uses
=--no-daemon --max-workers=2 --no-build-cache=. The dependency cache contains
Gradle modules, wrapper distributions and Cargo inputs, not build outputs.

=android-device= installs and launches the debug APK on one accelerated x86_64
emulator. It runs =NativeEngineProbeTest= and =EngineAdapterTest=, requires every
declared case to execute without skips, and checks logcat for crashes and hangs.
Diagnostics include the APK digest, device ABI, page size, API level, launch
output and instrumentation results. The script bounds waits and cleans up the
emulator and adb server it started; it refuses occupied ports and a device whose
ABI is not the one its system image implements.

* Inputs

=android/tools/ci/inputs.sh= reads the toolchain catalog, Gradle wrapper and
qualified ABI declaration rather than maintaining separate CI versions. The
emulator image it names is the pinned platform for the qualified ABI of the host
architecture, since an accelerated emulator implements its own host.

#+begin_src bash
android/tools/ci/inputs.sh
android/tools/ci/inputs.sh --packages
android/tools/ci/inputs.sh --install --print
android/tools/ci/inputs.sh --install
#+end_src

Installation requires SDK command-line tools under =ANDROID_HOME= (or
=ANDROID_SDK_ROOT=) and =rustup= on =PATH=. It installs the selected SDK packages
and pinned Rust toolchain/targets, accepting package licence prompts.
=--print= previews the commands without installing anything.

* Device Gate

The gate runs on the standard GitHub-hosted =ubuntu-24.04= x64 runner. No
repository variable or self-hosted runner is required. CI uses no GitHub App
credentials, private corpus or release signing secrets.

The job grants access to =/dev/kvm= and confirms acceleration with
=emulator -accel-check= before any boot. An
accelerated emulator implements its host's architecture, which is why the image
is derived rather than configured: =inputs.sh= reads =uname -m=, refuses a host
architecture the build does not qualify, and names the pinned platform for that
ABI. The device gate then refuses a device that is not that image's ABI.

The job installs the pinned SDK packages, emulator, image, Rust toolchain and
every declared target rather than relying on preinstalled versions.

An x86_64 emulator run qualifies loading and querying the packaged x86_64 engine
on a 4 KB kernel. It is neither ARM64 device qualification nor 16 KB-kernel
qualification: those remain the local ARM64 device run's evidence, and a clean
cross-build alone qualifies no runtime.
See [[https://docs.github.com/en/actions/reference/runners/github-hosted-runners][GitHub-hosted runners]] and [[https://developer.android.com/studio/run/emulator-acceleration][Android emulator acceleration]].

The hosted device run remains pending until it passes on reviewed master.

* Local Checks

From =android/=, after provisioning the SDK and toolchain:

#+begin_src bash
./gradlew --no-daemon --max-workers=2 --no-build-cache \
  :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease \
  :app:testDebugUnitTest :app:lintDebug
tools/verify-native-packaging.sh \
  app/build/outputs/apk/debug/app-debug.apk \
  app/build/outputs/apk/release/app-release-unsigned.apk
tools/verify-private-storage.sh \
  app/build/outputs/apk/debug/app-debug.apk \
  app/build/outputs/apk/release/app-release-unsigned.apk
tools/ci/inputs-tests.sh
tools/ci/verify-device-smoke-tests.sh
tools/ci/verify-device-smoke.sh --page-size 4096
#+end_src

The device script requires Bash for process-group deadlines. It accepts
=DEVICE_SMOKE_ADB=, =DEVICE_SMOKE_EMULATOR=,
=DEVICE_SMOKE_AVDMANAGER=, =DEVICE_SMOKE_AAPT2= and =DEVICE_SMOKE_GRADLEW=
tool overrides. =DEVICE_SMOKE_SERVER_PORT= and =DEVICE_SMOKE_CONSOLE_PORT=
isolate parallel runs; =DEVICE_SMOKE_RESULTS= selects the results tree.
=DEVICE_SMOKE_*_LIMIT= variables bound individual stages.
