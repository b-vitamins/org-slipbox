#+title: org-slipbox Android GitHub Authorization

* Contract

Slipbox uses one project-owned public GitHub App. Users authorize in the system
browser and install it on selected repositories; they do not register an App,
provide a PAT, configure a client ID or run a server. Anonymous public HTTPS
sources remain independent.

The authorization component returns the verified account, installation access
and credential. Token renewal, repository selection and connection navigation
are separate responsibilities. See [[file:android.org][the reader contract]] and
[[file:android-build.org][build instructions]].

* Public Configuration

=android/github-app.properties= supplies =clientId= and =installationUrl=,
packaged as =GITHUB_CLIENT_ID= and =GITHUB_INSTALLATION_URL=. These are public
values, not credentials. An empty client ID leaves clean builds usable and
authorization unavailable; an absent installation URL removes the install offer.

A development build can override the client ID:

#+begin_src bash
./gradlew :app:assembleDebug -Pslipbox.githubClientId=<public-client-id>
#+end_src

Configuration rejects credential-like prefixes, excessive length and non-HTTPS
installation URLs without repeating the supplied value. No client secret,
private key or PAT is packaged.

* Device Flow

| Request | Endpoint |
|---------+----------|
| Device code | =POST https://github.com/login/device/code= |
| Token polling | =POST https://github.com/login/oauth/access_token= |
| Verified account | =GET https://api.github.com/user= |
| Installation access | =GET https://api.github.com/user/installations= |

The device grant sends the client ID and device code without a secret or OAuth
repository scope. Polling respects GitHub's interval; =slow_down= adds five
seconds. Denial, expiry and service faults produce typed outcomes. The stored
token expiry is dated at the token response, before account verification.

Browser return alone does not settle authorization. Replacement, cancellation,
lifecycle destruction and composition disposal withdraw the active attempt.
An in-flight exchange is bounded by its transport deadline; withdrawn attempts
drop queued callbacks.

HTTPS exchanges run off the UI thread, without redirects or unbounded response
bodies. Diagnostics use closed error values and exception classes, not response
bodies or exception messages. Temporary codes are not saved in navigation state;
diagnostic representations redact codes and credentials.

* Result And Storage

=GithubAuthorization= contains =VerifiedAccount=, =InstallationAccess= and
=StoredCredential=. Account identity comes from GitHub; its stable numeric ID
scopes credentials and its renameable login is display-only. Authorization and
repository installation are distinct, so an account with no installation is
reported honestly.

=AuthorizationVault.keep= uses the asynchronous vault under:

#+begin_src text
VaultScope(sourceId, "github.com", account.id, credentialRef)
#+end_src

Vault creation, replacement and closure remain off the UI thread. The recipient
receives one result, and the vault closes after delivery.

* Renewal

=CredentialRenewalOwner= supplies a credential for one source, verified account
and credential reference. Calls block and must run off main. Access within one
minute of expiry is refreshed using the public client ID and device-flow refresh
grant; expiry is dated at the response. Non-expiring access is reused as stored.

Callers of one owner serialize re-read, exchange and vault replacement. The vault
lease excludes competing owners of the same record. Success follows commit;
closing suppresses delivery without discarding a rotation already in progress.
An uncertain or failed replacement returns =Uncommitted=. That owner then
re-reads the record without replaying the consumed refresh token.

Transient faults and required reauthorization retain offline data. Disconnect
removes the scoped credential and keys; =removeCache()= separately removes the
account's checkout, index, assets and reading state. Diagnostics omit credentials,
response bodies and exception messages. A transport fault does not establish
whether GitHub consumed the refresh token.

* Owner Setup

Register [[https://github.com/settings/apps/new][one public GitHub App]] for the project:

1. Use the project homepage, =https://github.com/b-vitamins/org-slipbox=.
2. Enable Device Flow and expiring user authorization tokens.
3. Leave callback/setup URLs empty, authorization during installation unchecked,
   and webhook Active unchecked.
4. Request Contents read-only and required Metadata read-only; no other permissions.
5. Allow installation on Any account.
6. Add the public Client ID and
   =https://github.com/apps/<app-slug>/installations/new= to the configuration.

See [[https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/registering-a-github-app][registration settings]] and [[https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app][GitHub App device authorization]].

A real grant still needs owner browser consent against a scratch repository
before qualification is complete. Automated tests use synthetic transports and
credentials; they do not perform or silently skip real consent. The manual
record states grant outcome, identity match, vault handoff and cancellation,
without archived codes, tokens or account-identifying screenshots.

* Manual Qualification

Real consent is a manual journey, not a test case. =LiveAuthorizationJourney= is
an instrumentation of its own, so no connected suite and no credential-free CI
reaches a step that waits for a person. It runs when it is named:

#+begin_src bash
android/tools/auth-smoke/live-auth.sh cancel OUTPUT_DIR
android/tools/auth-smoke/live-auth.sh grant OUTPUT_DIR EXPECTED_ACCOUNT
#+end_src

The launcher installs the assembled debug and instrumentation builds on one
attached device and starts the journey with =am instrument -w=, supplying:

| Argument | Meaning |
|----------+---------|
| =stage= | =cancel= withdraws one real code request; =grant= asks for consent |
| =resultDir= | absolute device directory for this run's outcome |
| =expectedAccount= | numeric account a grant must match; =grant= only |
| =consentSeconds= | approval window, within one code's lifetime |

A missing or unusable argument fails by argument name without repeating what was
supplied. =ADB=, =SERIAL=, =APP_ID=, =TEST_ID=, =CONSENT_SECONDS= and =RUN_LIMIT=
select the tool, device, installed identities, window and deadline; starting and
stopping a device belongs to the caller.

A grant shows the verification code on the device screen alone. Enter it at
GitHub's verification page and approve; an unapproved window lapses into a
withdrawal rather than outliving the code. The run then checks the verified
account against the expected one, requires installation access on selected
repositories, keeps and reads back the credential in a namespace of its own,
withdraws a second request before approval, and removes what it made.

=live-auth.json= in =resultDir= is collected, then removed from the device. It
carries the stage and that run's outcomes: grant, identity match, selected
installation, vault handoff and readback, cancellation, owned cleanup and pass.
No code, token, account, repository or path is reported, and no screenshot, UI
dump or logcat is taken.
