#+title: org-slipbox Android Document Content View

* Scope

=DocumentContentView= embeds the standalone Org renderer in a Compose-hosted
WebView. It accepts Org text and explicit presentation inputs, reports navigation
intents and resolves source-bound assets. Native screens own destinations,
previews and repository access; the content view owns none of them.

The application bundles the renderer, not the web client. No desktop daemon,
loopback server or downloaded renderer is needed. The reader contract is in
[[file:android.org][android.org]]; build instructions are in [[file:android-build.org][android-build.org]].

* Packaging

=:app:documentBundle= installs the web client's locked npm dependencies and runs
=build:document=. It verifies emitted names, lengths and SHA-256 digests against
=assets.json=, then excludes the demonstration =host.html=. Each
=stageDocumentAssets<Variant>= task registers the verified tree as generated APK
assets. Generated JavaScript, styles and fonts are not committed.

| APK asset                      | Origin                              |
|--------------------------------+-------------------------------------|
| =index.html=, =host.js=, =host.css= | application-controlled host      |
| =document.js=, =document.css=   | shared standalone renderer          |
| =assets/KaTeX_*=               | bundled math fonts                  |
| =assets.json=, =THIRD-PARTY-NOTICES.txt= | build inventory and licences |

* Local-content boundary

=WebViewAssetLoader= serves HTTPS at =appassets.androidplatform.net=. The
=/bundle/= handler serves only packaged document files. The =/asset/= handler
serves resolver-provided bytes under the live mount token. Every loader miss,
foreign-origin request and non-GET request receives an empty =404=, never a null
response that could fall through to the network. HTML subresources and all
navigation are refused. Responses use =nosniff= and =no-store=.

Network loads, file/content access, file-URL cross-origin permissions, DOM
storage, geolocation and window opening are disabled. Mixed content is refused;
WebView debugging follows the application's debuggable flag. JavaScript remains
enabled for the trusted bundled renderer, not for note-supplied scripts.

The host's Content-Security-Policy admits local scripts, styles, fonts and
images, with no connections, forms, frames or base-URL changes. Inline styles
support presentation variables and KaTeX error output; inline scripts are
forbidden. Org text crosses as escaped JSON and is parsed as data. Math uses
the shared renderer's untrusted KaTeX options and semantic MathML output.

* Caller interface

#+begin_src kotlin
DocumentContentView(
    source = DocumentSource(source, generation, id, filePath, org, baseLevel = 2),
    presentation = presentation,
    initialProgress = restoredProgress,
    restoreFocus = dismissedPreviewOrigin,
    onIntent = { intent -> /* application navigation */ },
    resolveAsset = DocumentAssetResolver { binding, target -> /* bytes or null */ },
)
#+end_src

The caller supplies the repository source identity, its exact content generation
and a document identity, not a bare note key shared across repositories. The
view issues its own opaque mount token. Any source-field change retires that
token; presentation-only changes retain it. Callback and resolver replacements
use their latest values without rebuilding the view.

| Intent    | Payload                         | Caller action                 |
|-----------+---------------------------------+-------------------------------|
| =Glance=  | link, gesture, viewport, origin | open a contextual preview     |
| =Pin=     | link and viewport               | open beside its origin        |
| =Go=      | link and viewport               | open as a fresh root          |
| =Dismiss= | none                            | withdraw the standing preview |

The =slipboxDocument= message channel validates origin, main frame, live token
and payload shape before delivering an intent. Unknown fields, verbs and
gestures are refused; messages are bounded to 4096 characters. Diagnostics name
the failed check, never the note-derived payload. No native evaluator, RPC
dispatcher, engine or credential object is exposed. A WebView without the typed
message-listener feature renders without navigation callbacks.

A glance origin is an opaque, mount-bound identifier for the exact link element,
not note content or a selector supplied by the note. After a native preview is
dismissed, the caller may return it through =restoreFocus=. The host focuses only
the still-connected element carrying that exact identifier and prevents the
focus operation from scrolling the document. Retired mounts and replaced
origins cannot receive focus.

ID links, indexed node keys, relative Org files and heading selectors all use
that typed channel; they are not asset requests. The Android host also
intercepts ordinary primary activation of browser-safe external anchors so the
native side can validate and dispatch them. The standalone web default keeps
normal browser navigation. Modifier and auxiliary-button activation remains
outside the typed channel and is subject to the embedding host's navigation
policy.

Asset lookup receives =DocumentBinding=, including the document's
repository-relative file path, and the verbatim Org target, such as
=file:../assets/diagram.png=, on the loader thread. The URL carries the UTF-8
target as one bounded hexadecimal component, so its slashes and =..= are opaque
to the local origin. The host rejects invalid encodings and stale mounts; the
resolver normalizes relative components and enforces repository containment.
It never uses the currently selected source. An in-flight lookup retains its
captured binding. Null results and refused MIME types return =404=.

The production resolver accepts signature-matching PNG, JPEG, GIF and WebP
images up to 12 MiB for inline display. A bare resolved image is responsive,
bounded to the reading viewport and carries a useful filename-based accessible
name; a load failure becomes a quiet named unavailable state. Labeled file links
retain their established anchor behavior, and a missing resolver preserves the
web renderer's readable inert text.

Explicit image and UTF-8 text attachments may be handed to another application
up to 32 MiB. The file is copied from the mounted generation to an opaque private
cache slot, then shared through one non-exported =FileProvider= URI with only
=FLAG_GRANT_READ_URI_PERMISSION=. The provider root contains staged attachments,
not repository content; the intent carries one URI in both data and =ClipData=.
Executable formats, including HTML and SVG, are never served. HTTP(S) targets do
not enter the asset resolver and remain explicit browser navigation.

* Presentation and lifetime

=DocumentPresentation= supplies per-mount theme, typography, geometry and motion.
The host applies its CSS variables and fixes =textZoom= at 100: Android font
scaling is already incorporated, including nonlinear large-text scaling.
Presentation updates preserve document nodes, scroll, focus and previews.
Source changes use the renderer's =update= contract and withdraw old previews.
One normalized =initialProgress= is applied after a new mount lays out; later
recomposition of that live mount never reapplies it. Link intents snapshot the
current normalized viewport so native Back can restore the origin.
Disposal retires the token, invokes renderer teardown and destroys the WebView;
the caller withdraws its own preview when removing the content view.

AndroidX WebKit is pinned to =1.15.0= to retain API 23 compatibility; newer lines
require API 24. Dependency locks and checksums are generated by Gradle.
JVM and packaged-WebView tests cover the channel, escaping, settings, offline
bundle inventory, scoped assets, lifecycle and readable light/dark presentation.
